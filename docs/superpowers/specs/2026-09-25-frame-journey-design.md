# «Путь кадра» — спецификация

Дата: 2026-09-25. Статус: дизайн утверждён в чате (целиком, акцент VOD, Artifact + папка, смарт-ТВ по мотивам специфики Okko).

## 1. Цель и аудитория

Интерактивная страница о том, как работает онлайн-кинотеатр: от мастер-файла студии до кадра на экране телевизора. Главный зритель — технический директор крупного российского онлайн-кинотеатра (ориентир — Okko: большой просмотр на смарт-ТВ, фильмы и сериалы плюс спорт). Он знает основы, поэтому страница выигрывает только настоящей механикой и точными деталями.

**Критерии успеха**

1. В первую секунду виден живой плеер с настоящим видео и настоящей телеметрией.
2. Всё, что можно сделать по-настоящему, сделано по-настоящему: кадры, кодирование, байты сегментов, декодирование, качество (PSNR), выпуклая оболочка, шифрование cbcs.
3. Моделируется только то, чего в браузере нет: сеть, CDN, тысячи зрителей, лицензионный сервер. Модели подписаны как модели, формулы видны.
4. Каждая цифра об индустрии — со ссылкой на источник. Иллюстративные данные подписаны.
5. 0 ошибок в консоли, работает двойным кликом (`file://`) и как Artifact.

## 2. Ограничения

- Правила коллекции `BRIEF.md` (opus-100-projects): `file://` без сборки и сервера, без ES-модулей и `fetch` к локальным файлам, Worker только из Blob, шрифты с кириллицей из Google Fonts с запасными, `requestAnimationFrame` с остановкой при `document.hidden`, DPR, без `alert`, русская типографика, запрет «ИИ-вида», функциональный текст ≥ 12 px.
- Artifact: CSP разрешает скрипты только с CDN из белого списка и шрифты Google; всё остальное — внутри страницы. Публикуется одним HTML-файлом, который собирает `tools/build.mjs`.
- Бренды: сервис на странице вымышленный. Okko и другие реальные компании упоминаются только в фактах со ссылками.
- Язык интерфейса и текстов — русский.

## 3. Главная идея

**Страница сама работает как онлайн-кинотеатр.** Браузер зрителя:

1. «Снимает» тестовую короткометражку «Восемь планов» (процедурно, WebGL2 + Canvas 2D, 24 кадра/с, 64 с).
2. Режет её на планы детектором склеек.
3. Кодирует в лесенку из пяти качеств H.264 через WebCodecs (ферма: пять кодировщиков работают параллельно).
4. Упаковывает в CMAF (свой fMP4-мультиплексор), строит манифесты HLS и DASH, шифрует байты по схеме cbcs (WebCrypto).
5. Отдаёт сегменты через модель сети и CDN.
6. Проигрывает собственным плеером: ABR-алгоритм, буфер, декодер WebCodecs, вывод на холст.

Если WebCodecs недоступен, включается модельный режим (размеры сегментов по модели сложности, показ через масштабирование исходника) с заметной пометкой.

## 4. Фильм «Восемь планов»

Детерминированная функция `кадр = f(номер кадра)`, 1280×720, 24 кадра/с. Каждый план проверяет кодек на своей слабости.

| № | План | Длит. | Что проверяет |
|---|---|---|---|
| — | Полосы и тон (SMPTE) + слейт + отсчёт с «2-pop» | 6 с | Лидер мастера; почти бесплатен для кодека |
| 1 | Рассвет над морем | 7 с | Бандинг на градиентах |
| 2 | Мультфильм | 7 с | Плоская заливка: мало бит (довод за per-title) |
| 3 | Ночной город под дождём | 8 с | Высокие частоты, движение, тёмные сцены |
| 4 | Из окна поезда | 7 с | Быстрое движение и параллакс |
| 5 | Крупный план | 7 с | Статичность; лица и детали важны для глаза |
| 6 | Архивная плёнка | 7 с | Зерно — самое дорогое для кодека (синтез зерна в AV1) |
| 7 | Огонь и искры | 7 с | Хаотичные частицы |
| 8 | Титры | 6 с | Резкий текст: важнее разрешение, чем битрейт |
| — | Затемнение | 2 с | Фейды |

Сумма: 64 с = 1536 кадров = 32 сегмента по 2 с. В углу кадра — служебная прожигаемая подпись (таймкод и номер качества), как на скринерах; так видно, из какого качества пришёл кадр.

## 5. Движок (модули)

Все модули — обычные скрипты в пространстве имён `FJ`, чистая логика оформлена так, чтобы её можно было подключить в node для тестов.

| Модуль | Ответственность | Интерфейс |
|---|---|---|
| `util` | формат чисел по-русски, случайные числа с зерном, easing, DOM, цикл rAF с паузой при скрытии | `FJ.fmt`, `FJ.rng`, `FJ.loop` |
| `charts` | примитивы графиков на Canvas: оси, ступеньки, области, полосы | `FJ.chart.*` |
| `film` | рендер кадра по номеру; таблица планов | `film.render(i)`, `film.shots`, `film.canvas` |
| `farm` | кодирование фильма в лесенку; события прогресса; модельный режим | `farm.start()`, `farm.on('segment')`, `asset` |
| `asset` | хранилище кадров и сегментов по качествам, статистика, манифесты | `asset.segment(r, k)`, `asset.hls()`, `asset.mpd()` |
| `mp4` | fMP4-мультиплексор (init + media segment) и разбор боксов | `mp4.init(r)`, `mp4.segment(r, k)`, `mp4.parse(bytes)` |
| `h264` | разбор NAL, SPS и заголовка слайса (для байтовой карты и cbcs) | `h264.nals(bytes)` |
| `net` | трассы пропускной способности, время загрузки с RTT | `net.trace(name)`, `link.download(bytes, t)` |
| `abr` | Throughput/EWMA (в духе hls.js), BBA-0, BOLA (как в dash.js), RobustMPC | `algo.decide(state) → {rung, brain}` |
| `player` | планировщик загрузок, буфер, остановки, декодер WebCodecs, вывод кадров, метрики QoE | `new Player({asset, algo, device, trace, canvas})` |
| `devices` | профили устройств: ТВ 4K, старый ТВ, приставка, телефон, ноутбук | `FJ.devices` |
| `cdn` | модель раздачи: города, узлы, кэши (LRU по Че и предзаливка), лавина запросов | `cdn.step(dt)`, `cdn.metrics` |

Плеер моделирует время загрузки, но декодирует и показывает настоящие кадры выбранного качества. Остановка буфера — настоящая остановка картинки.

## 6. Главы страницы

Сверху закреплена «линия сигнала»: Мастер → Планы → Кодек → Лесенка → Упаковка → CDN → Плеер → ТВ → Эфир → Масштаб, с живыми метриками.

0. **Сеанс (герой).** Плеер вымышленного сервиса показывает фильм; справа телеметрия (качество, битрейт, буфер, оценка сети, кодек, выпавшие кадры); снизу — мультивьюер из пяти контрольных мониторов с подписями качеств. Кадр красив без взаимодействия.
1. **Мастер.** Сколько весит несжатое видео (калькулятор: разрешение, частота, разрядность, субдискретизация) и мастер-файлы студий. Лупа по живому кадру: Y, Cb, Cr и 4:2:0. Живые осциллограф (waveform) и вектороскоп кадра.
2. **Планы и ферма.** Детектор склеек на живом сигнале (график разности кадров, найденные и настоящие склейки). Тепловая карта «качество × сегмент» заполняется по мере работы кодировщиков.
3. **Кодек.** «Сейсмограф» размеров настоящих кадров: ключевые кадры, склейки, зерно, фейды. Выравнивание GOP между качествами. Проверка кодеков и аппаратного декодирования этого устройства (WebCodecs, MediaCapabilities).
4. **Лесенка.** Настоящий эксперимент per-title/per-shot: кодирование отрывков каждого плана в сетке «разрешение × битрейт», PSNR на GPU, выпуклые оболочки, распределение бит с постоянным наклоном и итоговая экономия против фиксированной лесенки — числа посчитаны в браузере зрителя.
5. **Упаковка и защита.** Байтовая карта настоящего сегмента fMP4 (ftyp/moov, styp/moof/traf/trun/mdat, NAL-блоки). Шифрование cbcs: шаблон 1:9, открытые заголовки слайсов, WebCrypto. Живые манифесты HLS и DASH из фактических размеров сегментов. Цепочка лицензии (EME → CDM → сервер лицензий), уровни защиты, HDCP. A/B-водяные знаки: сессия кодируется выбором вариантов сегментов, «пиратская копия» раскрывает номер сессии.
6. **Раздача.** Карта городов без границ: ориджин, шилды, кэши у провайдеров. Суточная кривая с вечерним пиком и ночной предзаливкой. Каталог по Ципфу: LRU (аппроксимация Че) против предзаливки. События: «премьера в 00:00», отказ узла, выключение request collapsing.
7. **Плеер.** Гонка четырёх ABR-алгоритмов на одной трассе: у каждого своё видео, буфер и остановки. Панели «мысли алгоритма»: EWMA и запас, карта буфера BBA, очки BOLA по ступеням, дерево MPC на 5 сегментов. Трассы (оптика, Wi-Fi, 4G, 3G в поезде, туннель) и своя трасса, нарисованная мышью. Переключатель устройства. Водопад старта до первого кадра.
8. **Смарт-ТВ.** Интерфейс «с дивана» с пультом: предзагрузка по фокусу сокращает старт. Зоопарк платформ (Tizen, webOS, Android TV, tvOS, отечественные ОС) и версии движков. Ограничения памяти и декодеров и их влияние на ABR. Калькулятор «диагональ × расстояние → пикселей на градус»: когда 4K заметен.
9. **Эфир.** Для спорта на той же платформе: разбивка задержки по этапам и ролик «ГОЛ!» — кто из соседей увидит гол раньше.
10. **Масштаб.** Метрики QoE и их влияние на просмотр, рекорды нагрузки, что ломается первым. Источники.

## 7. Визуальная система

- **Мир:** монтажная и аппаратная постпродакшна. Нейтрально-графитовый фон (в колор-грейдинге окружение нейтральное, чтобы не сбивать восприятие цвета), мониторы с подписями, таймкоды, настроечные полосы.
- **Палитра:** фон `#18191B`, панели `#202124`, линии `#34363B`, текст `#ECEBE7`, приглушённый `#A4A6AB`, плейхед и эфир `#FF4D3D`, буфер и предупреждения `#FFB02E`, сеть `#6FB3FF`.
- **Цвета качеств — полосы SMPTE по убыванию яркости:** 720p `#D9D9D9`, 540p `#E6DA46`, 360p `#40D0D0`, 270p `#52C85C`, 180p `#D05CD0`.
- **Шрифты:** Sofia Sans Extra Condensed (заголовки, как в титрах и спортивной графике), Golos Text (текст), JetBrains Mono (данные, манифесты, байты, таймкоды). Handjet из первого плана убран при вёрстке: точечные цифры таймкода плохо читались.
- **Раскладка:** длинная страница из глав; на широком экране слева текст с закреплением, справа большая фигура; на телефоне всё в одну колонку, фигуры упрощены.

## 8. Производительность

- Кодирование фильма стартует сразу, плеер начинает после первых сегментов. На слабом устройстве верхнее качество отключается, если кодировщик не успевает.
- Фигуры работают, только пока видны (IntersectionObserver), и засыпают при `document.hidden`.
- Эксперимент per-shot запускается кнопкой и показывает прогресс.

## 9. Проверка

- Node-тесты чистой логики: ABR (ожидаемые решения BBA, BOLA, MPC на известных входах), аппроксимация Че против прямой симуляции LRU, мультиплексор и разбор боксов (круговая проверка), манифесты.
- Playwright: скриншоты десктопа и телефона, 0 ошибок консоли, проверка главного взаимодействия каждой главы; проверка настоящего декодирования; валидность fMP4 — проигрыванием через MSE в тесте.
